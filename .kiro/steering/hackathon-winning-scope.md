# Delivery Guardian — Kiro project steering

Read [AGENTS.md](../../AGENTS.md), [approved product scope](../../docs/product-scope.md), [official hackathon rules research](../../docs/hackathon-requirements.md), and [customer voice](../../docs/customer-voice-opportunity-research.md) before proposing or editing code.

**Always optimize for the highest-quality, on-time, zero-dollar hackathon submission.**
The owner selected **#11 Delivery Guardian + #1 DoneProof + #5 Ring Resolution** as one product. The primary track is Alexa+: a **genuinely runnable MCP Streamable HTTP server (MCP 2025-11-25+) and web client**. Ring is an optional verified sandbox/device addition, not a substitute for working core code.

**Implementation order:** first protocol/runnable client; then package intake/persistence; then independently verifiable action ledger; then source-aware event reasoning and support resolution; then Ring Playground only if accessible; then demo and submission. Do not implement excluded future features in the hackathon week without explicit owner decision.

**Permanent credit and spending rules:** Never autonomously initiate credit-consuming work or paid resources. Leave at least one Kiro credit unused with extra headroom for unbounded request costs; check current balance before any owner-authorized use. Prepare comprehensive requirements, tests and all acceptance criteria before prompting any coding agent. No Kiro cloud sessions or unattended crew work without explicit approval.

**Accuracy guardrails:** Carrier marking delivered is not proof of the customer's receipt. Ring activity is not proof of a package delivery. Sandbox/fixture evidence must be visible as sandbox/fixture. AI action result is `verified` only to the extent justified by a real read-back or other external evidence. Do not make affiliation/production Alexa+ connectivity claims.

**Definition of done:** Working end-to-end demo, automated tests, clean-room free setup, precise statements of what is integrated, mobile-friendly interface, honest friction log, under-three-minute video and Devpost submission before October 23 noon Pacific. Never report completion based only on generated code or a successful HTTP 200.
